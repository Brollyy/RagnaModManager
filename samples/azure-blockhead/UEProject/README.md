# Azure Blockhead UE 4.27 project

Open `RMMAzureBlockhead.uproject` in UE 4.27 on Windows. Generated editor `Content/` assets are not checked in; the authored assets are regenerated from the adjacent original OBJ and PNGs at the package paths used by the manifest. Its Windows target is explicitly `PCD3D_SM5`, matching Ragnarock on PC.

The OBJ, MTL, and PNG files in the parent `Source/` directory are the editable source art. Run `Scripts/create_hammer_materials.py` to import the body-color atlas, linear gauge ramp, and in-game icon. The body atlas keeps a normal mip chain and uses inset UV islands; the linear gauge ramp disables mip generation, uses bilinear filtering, clamps U/V, and disables sRGB. The optional selector PNGs stay in `Source/`; the default project does not import or package them because custom selector materials caused crashes in sample testing. The script builds a fixed body material, a `handleGauge` handle-bar material, and a two-stage head-bar material driven by `handleGauge` and `circularGauge`. The gauge materials use the stock default hammer's blue `centerColor` `(0.030109, 0.079745, 0.320833)` and orange `mainColor` `(1.0, 0.400337, 0.0)`. Then run `Scripts/reimport_azure_mesh.py` to import `SM_RMM_AzureBlockhead.obj` as the game-oriented Static Mesh and assign those materials to its `M_Character`, `M_JaugeManche`, and `M_JaugeTete` slots. The mesh generator creates valid UV area on every gauge face and splits vertices at hard box edges so UE can calculate stable tangents and flat normals. It also flips atlas V coordinates to account for PNG's top-left pixel origin versus OBJ's bottom-left UV origin. The project enables both the **Python Editor Script Plugin** and **Editor Scripting Utilities** plugin, which the automation uses. If you are enabling plugins in another project, enable both and restart the editor before running the scripts in order. You can use UE's File → Execute Python Script menu, or run the commandlet from `Scripts/` in a Windows Command Prompt (replace the UE install path if needed):

```bat
set UE427=C:\Program Files\Epic Games\UE_4.27
"%UE427%\Engine\Binaries\Win64\UE4Editor-Cmd.exe" "..\RMMAzureBlockhead.uproject" -run=pythonscript -script="%CD%\create_hammer_materials.py"
"%UE427%\Engine\Binaries\Win64\UE4Editor-Cmd.exe" "..\RMMAzureBlockhead.uproject" -run=pythonscript -script="%CD%\reimport_azure_mesh.py"
```

Running both scripts recreates the editor assets under `Content/RMM/Hammers/azure-blockhead/`; the cooked `.rhammer` samples are in the parent directory. A clean Windows `PCD3D_SM5` cook produces the shared shader archive, which `build_rhammer.py` validates and includes. Its default archive excludes the unused selector materials and textures. V11 contains 16 cooked UE package files and the shader archive. Its v11 icon and upright Changing Room preview are confirmed in `../Verification/ChangingRoom-v11.png`, and the race mesh and corrected atlas colors are visible in `../Verification/Race-Azure-v11-texture.png`. Narrow striping near the head/gauge edge remains visible. Blue-to-gold buildup and the combo-drop reset still need in-game confirmation with valid input.
